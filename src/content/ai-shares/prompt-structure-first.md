# 把模糊需求拆成可执行 Prompt 时，我会先固定输出结构

很多人第一次用 AI，习惯直接把脑子里的需求整段扔进去，然后等它“猜”自己想要什么。这样不是完全没用，但结果经常飘，尤其一旦任务开始涉及页面改版、文案整理、功能拆分或者多轮迭代，模型给出的内容会越来越不稳定。

我现在更稳定的做法，是先固定一套结构，再把内容填进去。结构本身通常只有四段：目标、输入、限制、输出。目标定义这次到底要解决什么，输入说明已有信息，限制负责收边界，输出则明确最后要交付成什么样。

## 为什么我越来越看重“输出格式”

如果没有输出格式，模型会自己决定该写成长段解释、列表、代码片段，还是混合输出。第一次看似乎还行，但一旦你要继续追问、对比多个方案或者把结果接进工作流，格式漂移会很明显。

我更倾向一开始就把输出结构钉住，比如：

1. 先给结论。
2. 再给 3 个执行步骤。
3. 最后列风险或注意事项。

这样模型不只是在“回答问题”，而是在按你预设的容器填内容。容器稳定了，内容才能连续迭代。

## 我现在常用的 Prompt 骨架

```text
目标：
我要完成什么。

输入：
我已经有的页面、文案、代码或上下文是什么。

限制：
不要做什么，必须保留什么，风格和边界在哪里。

输出：
请按固定格式返回，例如：
1. 先给简短判断
2. 再给可执行方案
3. 最后给风险或下一步
```

这个骨架看起来很朴素，但它的价值就在于能不断复用。无论是让 AI 帮我写首页模块、整理一篇技术分享，还是重写一段描述文案，我都尽量先把任务塞进这个外壳里。

## 真正省时间的不是“问得花”，而是“改得少”

我现在判断一个 Prompt 是否好用，标准不是第一次回答有多惊艳，而是第二轮、第三轮继续迭代时，是否还能稳定地往前推。只要模型每轮都保持差不多的输出结构，我就可以很快定位需要修改的是目标、限制，还是输入信息本身。

所以对我来说，Prompt 不是“魔法咒语”，更像一个小型接口设计。先把输入和输出做稳，AI 才能真正接进日常工作流，而不是每次都像重新碰运气。
